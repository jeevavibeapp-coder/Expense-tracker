32: /**
33:  * Settings, privacy, help, and the first-run introduction.
34:  *
35:  * These four screens are the ones that have to be *true*. Everywhere else a
36:  * wrong word costs a moment of confusion; here it costs the user's trust in
37:  * an app that reads their bank messages. Two rules follow from that, and both
38:  * are load-bearing:
39:  *
40:  *  - Say what is never read, not only what is. "Never personal messages,
41:  *    never OTPs" is the sentence people are actually looking for, and it is
42:  *    on screen before the permission is asked for rather than after.
43:  *  - Never offer a control that cannot work. An "Allow SMS access" button in
44:  *    the no-SMS flavour asks for a permission this APK does not declare: the
45:  *    request is denied instantly by the system, and the user is left tapping
46:  *    a button that will never do anything.
47:  */
48: 
49: /**
50:  * Three genuinely different situations, not two.
51:  *
52:  * [UNAVAILABLE] is the no-SMS flavour, where the permission is not in the
53:  * manifest at all. Collapsing it into [DENIED] would put an Allow button in
54:  * front of a user who has nothing to allow.
55:  */
56: enum class SmsAccess { GRANTED, DENIED, UNAVAILABLE }
57: 
58: /** The same three states in :core's terms, for asking it what to offer. */
59: val SmsAccess.capture: ManualEntry.Capture
60:     get() = when (this) {
61:         SmsAccess.GRANTED -> ManualEntry.Capture.AUTOMATIC
62:         SmsAccess.DENIED -> ManualEntry.Capture.OFF
63:         SmsAccess.UNAVAILABLE -> ManualEntry.Capture.NONE
64:     }
