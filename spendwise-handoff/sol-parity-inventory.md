# Independent three-app feature inventory and native parity

**Evidence label: TRACED applies to every feature, mapping, limitation and source-absence conclusion in this document.** This is a source inventory, not a browser, emulator, phone or accessibility test. Three source passes were compiled independently and then compared. No Opus parity matrix was read.

Snapshots:

- React: 2fa8dc04461e3966f2db9c60181ce3effe79fa24 (requested main baseline).
- Flask and native: 47dece72ab90a6f6a8a137a89ced08134fdb2124.
- React scope: App.tsx, components, store.ts, entry/config and relevant old Android wiring.
- Flask scope: served templates/routes and wired analytics, learning, sender, fraud and backup code.
- Native scope: android/nativeapp plus core.

**Full** means a reachable native UI/path implements the capability in the stated scope. **Partly** means a substantive part exists but a field, control, period, explanation or data scope differs. **Not at all** means no corresponding user path was found in the enumerated native sources. Equivalent native navigation or local parsing can satisfy a capability without copying a web layout or Gemini dependency. These ratings do not certify correctness: open parser, dedup, fraud, timestamp, contrast and document-I/O findings still qualify present functionality.

Path keys: N/ = android/nativeapp/src/main/java/com/jeevavibeapp/spendwise/; C/ = core/src/main/kotlin/com/jeevavibeapp/spendwise/core/. Flask references such as app.py:739 are relative to python_app/spendwise/. React references are repository-relative. Lines refer to the snapshots above, not the live working tree.

## Material parity differences (TRACED)

- No Activity category/date/type/source/review filter controls or sort chooser; text search remains (N/ui/Screens.kt:226; N/NativeMainActivity.kt:1323). Native CSV exports all active rows (N/data/Repo.kt:1294), whereas React exports filtered results (App.tsx:367).
- React manual recurring rules and due-occurrence creation are absent. Native and Flask infer future bills; this is not a scheduler (store.ts:86, :185; C/Analytics.kt:31).
- Native has month reports but no React week/year modes (N/ui/Report.kt:181). Cash-flow and category trends cover six months (C/Insights.kt:91, :117); React historical views cover every represented month (App.tsx:348, :388). No native income-source donut, all-time category donut, overall adherence percentage or exact 10%-alert equivalent was found.
- Native omits Flask display-name and display-currency preferences (N/ui/SettingsAndOnboarding.kt:211, :250). Neither version performs exchange conversion. Local native single-user storage intentionally has no web signup/login.
- Manual threshold sliders do not implement Flask correction-rate adaptation (python_app/spendwise/app.py:558; C/Engine.kt:159). Category name/type creation exists, but React/Flask color selection is absent (N/NativeMainActivity.kt:941).
- Native omits parts of Flask confidence/reason previews, the immediate one-capture category modal and dismiss-all-prompts behavior. Group review is not equivalent to all these controls (N/ui/Review.kt:33).
- Native acknowledgement hides an alert; Flask distinguishes safe/dismissed and retains visible resolved history (python_app/spendwise/templates/fraud.html:36; N/ui/Screens.kt:578).
- Native improves Flask history caps: Flask Activity limits 200 and merchant figures/list limit 100 (app.py:816, :1195); native streams active rows and all matching merchant history (N/data/Db.kt:210; N/ui/Merchant.kt:542).
- Both advertised full JSON backups omit user-visible state, including held messages, fraud history and parse diagnostics. Profile is omitted by both backup baselines. Native preserves the currency value in backup/restore even though it exposes no currency editor (N/data/Repo.kt:1184, :1252). Legacy timezone and stream-I/O limitations remain (N/data/Repo.kt:1158; C/Backup.kt:241, :699; python_app/spendwise/backup.py:42).

## Older behavior which is not a requirement to copy (TRACED)

1. **Automatic React SMS intake is not a proven working capability of the shipped Android path.** App.tsx:115 registers only a live Capacitor listener while React is mounted. android/app/src/main/java/com/jeevavibeapp/spendwise/MainActivity.java:63 replaces the React assets with Flask once ready. SpendWisePlugin.java:29 reports granted=true without a real permission request. SmsReceiver.java:28 forwards only to the current plugin instance and keeps no durable queue. Do not count a successful phone auto-import as something native must port from React. This is a structural trace, not evidence that no developer ever made a transient setup run.
2. **Manual browser SMS paste remains a conditional feature**, not automatically excluded by the phone disconnection; it may run with configured key/network. No live Gemini service was tested.
3. Express/server.ts is not the React data path here: App.tsx:51 imports store; reads at :128/:139/:154 call local store. Do not count unused endpoint features.
4. PWA metadata exists in manifest.json, but inspected tree has no service-worker file/registration. Local CRUD works from loaded assets without network; install/cold-load offline was not verified.
5. No exposed React sign-in, full-backup restore, inbox scan, fraud review, merchant-resolution queue, notification or recurring-schedule-management UI exists in App.tsx/components/store.ts. Source-absence conclusion is limited to this surface.


These are **TRACED** observations about the Flask baseline. They should not be treated as capabilities the native app must reproduce faithfully.

1. **“Full merchant history” is actually the latest 100 rows.**  
   `app.py:1195` applies `LIMIT 100` before calculating total, average, visit count and trend; `templates/merchant.html:72` labels the list “All transactions.” With 101 purchases, the oldest is omitted from both list and figures.

2. **Activity cannot page through more than 200 matching rows.**  
   `app.py:816` applies `LIMIT 200`; `templates/transactions.html` has no pagination/load-more control. Search may locate an older known transaction, but ordinary browsing cannot reach the full ledger.

3. **Transfer/refund detection does not correct the primary totals, despite Help saying it does.**  
   `analytics.py:535`–`:561` returns gross income/expense to the Home hero; `flow` is separate. The adjusted result appears only in the explanatory card at `templates/dashboard.html:88`. `templates/help.html:179`–`:186` says these movements are excluded from totals. A matching ₹100 debit/credit can therefore produce a detected transfer and adjusted spending of ₹0 while the Home “Spent” total still includes ₹100.

4. **Changing only a transaction’s category does not necessarily teach future categorization.**  
   The edit handler calls `record_confirmation` only inside the changed-merchant branch, `app.py:1165`–`:1175`; it otherwise updates the transaction category at `:1176`. That does not fulfill the general “correct a category once and it remembers” promise in `templates/welcome.html:39` or `templates/help.html:138`. The separate category-modal and bulk-review paths do teach.

5. **Import unconditionally claims automatic capture is on.**  
   `templates/import.html:7`–`:10` always renders “Automatic capture is on,” without checking the denied/unavailable state that Settings handles. This message is false for a no-SMS build or denied permission.

6. **There is no exposed CSV import workflow.**  
   Import accepts one SMS textarea (`templates/import.html:18`); the route parses SMS text (`app.py:1237`). The JSON restore error telling users to “import a CSV” through Import (`backup.py:123`) points to a capability that is not implemented in that screen.

7. **Recurring bills are inferred, read-only observations—not scheduled transactions.**  
   `analytics.py:182` detects cadence from existing merchant expenses and returns predictions; Home renders them at `templates/dashboard.html:147`. There is no route/form for creating or editing a recurring rule, scheduling a transaction, marking a bill paid, or dismissing an inferred bill.

8. **“Full backup” has explicit exclusions.**  
   The allowlist at `backup.py:42`–`:61` does not include fraud alerts/history, held messages, parse-miss diagnostics, raw transaction SMS bodies/senders, profile name or onboarding state. It preserves the listed ledger/learning data, but not every user-visible state.

9. **Some backend-supported operations are not exposed as UI features.**  
   The `/transactions/<id>/confirm` route exists (`app.py:890`), and Activity computes candidate names (`app.py:835`), but the current Activity template does not render those candidate/confirm controls. Merchant correction remains accessible through editing, and bulk review exposes category suggestions. Similarly, category rename/recolor, arbitrary sender trust selection, and alert reopening have no displayed controls.
